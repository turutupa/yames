## What to build

1. **`src/paths/custom.ts`**: the `Recipe` type: `shape` (a closed set mapped to the templates: box,
   three-per-string, arpeggio, one-string climb, across strings; sweeps only if `sweepLoop` takes
   arguments a player can name: say), `root` (twelve pitch classes), `scale` or chord quality (the sets
   `src/jam/scales.ts` / `harmony.ts` already name), `position` (a fret, 0 to 15, or "the nearest box to
   the root on the low E"), `strings?`, `subdivision` (quarters, eighths, triplets, sixteenths), `bars`
   (1 to 8), `direction` (up, down, up and back). Closed sets only; a version number on the type.
2. **`buildCustomExercise(recipe)`** → `{ ok: true, exercise, summary } | { ok: false, why }`: the
   notes from the templates (never written by hand, never by a model), the tab through `parseTab`,
   playability through `checkReachAt` (a recipe a hand cannot play is refused with a `why` a sentence can
   be made from: `unreachable`, `tooFewNotes`, `outOfRange`), a starting tempo and the rung ladder
   (`maxPlayableBpm`; mock 17 starts at 60), grading **timing and notes heard only**, with default pass
   marks (read how a pack Exercise declares what it grades and what not; the custom one says the rest
   is not graded). An id derived from the recipe (stable: the same recipe gives the same id), never
   colliding with a pack Exercise id. `summary` is data (shape, root, scale, position, subdivision,
   bars, first note), not a sentence: t2c writes the sentence from locale templates.
3. **The variant chips' functions** (mock 17's "Sixteenths instead", "Next position"): `nextRecipe(r,
   change)` for subdivision, next / previous position, more / fewer bars, the other direction; each
   returns a recipe that builds or says why not.
4. **Tests**:
   - a grid over every shape × several roots × positions × subdivisions × bar counts: every result
     either builds and passes `validatePath` when wrapped in a one-Exercise Path document, or is refused
     with a `why`; never a throw;
   - the A minor pentatonic at the 5th fret in eighths, three bars, matches mock 17's notes (A on the low
     E at fret 5 first);
   - the same recipe gives the same notes and id twice;
   - **the scorer reads them**: write the grid's schedules to a fixture the Rust `path_exercises` test
     harness reads (`src-tauri/tests/path_fixtures/`, a second file beside `schedules.jsonl`, generated by
     a script you add under `scripts/`, the way `npm run paths -- gen` writes the first) and extend the
     harness to read it too. A test-only Rust change: no engine code.
5. Measure: the time to build one recipe on this machine (the preview must feel instant on a phone;
   say the number).
