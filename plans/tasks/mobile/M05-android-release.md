# M05 — Android release: a signed build people can install

Size: M. Branch: `mob/m05-android-release`, from `mobile` after M04
merges. Needs: M04 (background audio), M03d (polish). Produces: the
first public Android build.

## Goal

A signed release APK on GitHub Releases that installs on a phone, a
signed AAB uploaded to a Play closed test, the website's download
section offering Android, and the Play listing filled from
`store-listing.md`.

## Decisions already made

- Package id stays `com.yames.metronome`.
- Play App Signing on; the owner keeps the **upload** key. The
  keystore is generated by the owner, not by a worker: it is a
  credential. The brief tells the owner the exact command and the four
  GitHub secrets to create; the worker wires CI to them and never sees
  the values.
- One version string across all platforms (`package.json`,
  `src-tauri/Cargo.toml`, `tauri.conf.json`); Android `versionCode`
  derives from it in `gen/android/app/build.gradle.kts`
  (major*10000 + minor*100 + patch) so Play accepts each upload.
- The APK on Releases is arm64 only (`aarch64`); the AAB carries all
  four ABIs and Play splits it.
- The desktop `release.yml` is not touched. `android.yml` (from M05a,
  `workflow_dispatch`) becomes the real Android build: signed, with an
  input for the tag to attach assets to.

## What the owner does (one-time, before or during this task)

```bash
keytool -genkeypair -v -keystore yames-upload.jks -alias yames -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 yames-upload.jks > yames-upload.jks.b64
```

Then in the GitHub repo settings → Secrets: `ANDROID_KEYSTORE_BASE64`
(the .b64 content), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`
(`yames`), `ANDROID_KEY_PASSWORD`. Keep the `.jks` somewhere safe and
out of the repo; losing it means a new listing.

Also: create the Play developer account (`PLAY-CONSOLE-CHECKLIST.md`)
and recruit the twelve closed testers on day one — the 14-day clock
does not start until they opt in.

## Loose ends handed to this task by M04 (do them; they are small)

- **Portrait lock** in `gen/android/app/src/main/AndroidManifest.xml`
  (`android:screenOrientation="portrait"` on the activity). Every
  phone layout assumes it (M03c). Nobody has added it yet.
- **Remove the AndroidTV `leanback` `uses-feature`** the template put
  in the manifest; Yames is not a TV app and Play will list it as one.
- **A real monochrome notification icon** (`ic_stat_yames`, 24 dp,
  white on transparent, from the app mark) instead of
  `android.R.drawable.ic_media_play`.
- **Hide the sound-output device picker on mobile**
  (`DevicesSettingsSection`, behind `IS_MOBILE`): Android routes
  output itself and `set_audio_output_device` is inert there.
- **One sentence on the onboarding "ready" step on mobile** saying the
  phone will ask permission to show a "playing" notification the first
  time you press Play, and why (so the click keeps going with the
  screen off). Musicians' words. All 15 locales.
- **Prove R8 works with the plugin**: the release build is minified;
  install it and run the M04 emulator gates once (screen-off, call,
  Back, link). Add ProGuard keep rules only if something breaks and
  say which.
- **Read the granted audio mode from logcat** on the first real
  phone (`asked LowLatency/Shared, got …`) and record it in the
  release notes; the emulator refuses the fast path, a phone should
  not.

## Steps

1. Worktree sanity.
2. `gen/android/app/build.gradle.kts`: release signing config that
   reads the four values from environment variables (never from the
   repo), `versionCode` from the version string, `minifyEnabled` and
   `shrinkResources` for release, portrait lock confirmed in the
   manifest (M04 put it there; verify).
3. `android.yml`: decode the keystore from the secret into a temp
   file, export the variables, `npm run tauri android build --aab` and
   `--apk --target aarch64`, attach the APK to the GitHub release named
   by the `tag` input (`gh release upload`), upload the AAB as a
   workflow artifact. Strip the debug symbols (`llvm-strip`) is done by
   the release profile; verify the `.so` size in the report.
4. Build once locally with a throwaway keystore of your own to prove
   the gradle config, then delete it. Record APK and AAB sizes; the
   plan's 80 MB budget applies.
5. Install the release APK on the emulator: first run shows the
   three-step onboarding, click plays, settings persist across a kill
   and relaunch, the foreground notification appears with the screen
   off. Screenshots at 1080×2400 for the six-shot list in
   `store-listing.md` — the emulator's resolution is a valid Play
   phone screenshot size. Commit them under
   `plans/tasks/mobile/m05/store/`.
6. Feature graphic 1024×500 and the 512×512 icon export from
   `src-tauri/icons/`. Keep it to the existing mark and colours.
7. `docs/index.html` download section: an Android row linking the
   Releases APK, with a one-line "Install from the file, or wait for
   Google Play" note in plain words; the Play badge is added when the
   listing is live. `docs/privacy.html` already exists.
8. A `plans/tasks/mobile/M05-RELEASE-NOTES.md`: exactly what the
   owner clicks in Play Console, in order, referencing the checklist
   and the listing document, and the `gh workflow run android.yml -f
   tag=vX.Y.Z` command.

## Acceptance gate

- `android.yml` runs green on the `mobile` branch via
  `workflow_dispatch` against a draft release tag (ask the owner to
  create the draft tag, or document that this is the first thing they
  run); the APK it produced installs on the emulator with
  `adb install` and passes step 5. The owner may prefer to run this
  after `mobile` merges to `main`; if so, prove the equivalent locally
  with your throwaway keystore and say so.
- Sizes recorded: `.so` per ABI, APK, AAB.
- `matchMedia('(pointer: coarse)')` and `('hover: hover')` values
  inside the release APK's WebView on the emulator, and a screenshot
  proving zen shows its exit button there. (The M00 zen screenshot did
  not show it; find out why.)
- Desktop gates unchanged and green; `npm run build:mobile` clean;
  Android check clean.
