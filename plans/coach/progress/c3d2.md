## The pipeline (`pipeline.sh <candidate> <config>`)

Config files: `env/configs/*.sh` (KIND lora|full|stock, BASE, TRAIN_ARGS, QUANTS, GGUF, HELDOUT).
Stages, each skipped when its output exists (so a re-submitted job continues), each logged to
`runs/<c>/logs/<stage>.log` and to one line in `runs/<c>/STATUS` (started / done / skipped / failed + log):

1. **render** train + validation with `--check --with-grammar` (the prompt code of the checkout the
   job runs from) -> `data/*.rendered.jsonl`.
2. **lengths** (`token_lengths.py`, the Qwen3 tokenizer) -> `data/lengths.json`.
3. **train** (`train_lora.py ... --resume --epoch-snapshots`): a checkpoint every `--save-every` steps
   in `train/ckpt-a|b` (alternating; pointer `ckpt-latest.json` replaced atomically), so a stopped job
   loses at most `--save-every` steps; at the end of epoch 1 the validation loss and a snapshot
   `train/epoch-1`; the final model in `train/`.
4. **merge** (LoRA: `merge_lora.py`, peft `merge_and_unload`, bf16) and **gguf** (`convert.sh full`, each
   quant in QUANTS) for every snapshot -> `gguf/<snapshot>-<quant>.gguf`.
5. **val**: every GGUF through the frozen eval binary on the 525 validation records under each record's
   grammar (`val_match.py requests` rebuilds the AskRequest and checks the Rust head/tail rebuild the
   training prompt byte for byte; `score`: exact match as the same JSON object, per language and kind).
6. **select**: the best validation exact match at the FIRST quant (tie -> the later snapshot) -> `SELECTED`.
   Validation only.
7. **heldout** (HELDOUT=yes): `coach-eval.mjs model` on the selected GGUF (grammar situation, prompt
   notes, deadline 8 s: the stock models' flags), then `chain` rules-first and model-first. Every run of
   the held-out set appends a line to `heldout/COUNT`.
8. **tabulate** (`tabulate.mjs`) -> `RESULT.md`, with the stock rows beside the candidate.

Re-submit one (it continues): the same `job submit` with a new name (`-2`). The long jobs run from a
frozen code snapshot, `~/scratch/yames-c3d/code/b5170fca/` (`git archive` of this branch,
`node_modules` linked to the main checkout's), so removing this worktree does not break them.

Trainer changes (`train_lora.py`): a row longer than `--max-len` is dropped and counted
(`--cut-prompts` restores the old left cut); right padding passes no attention mask (a real token never
sees a pad under causal attention; `--mask-padding` restores the mask, which costs the fast SDPA path);
`--resume`, `--save-every` for LoRA and full; `--epoch-snapshots`. `resume_check.sh` (job 926) proved
checkpoint, resume and the epoch snapshot on 16 rows for both LoRA and full (the resumed step's loss
matches to the third decimal: GPU kernels are not bitwise deterministic).

## The trial (job 911 `coach-c3d2-trial`, `runs/trial-06b-lora/`): every stage but held-out proven

0.6B LoRA r16, 300 steps, batch 8, no grad checkpointing, load average ~50-65 (busy machine):
**5.95 s/step** steady (about 1,850 tokens/s), **peak 21.6 GiB** allocated. Training 30 min; render 4 min,
lengths 20 s, merge 30 s, Q8_0 13 s, Q4_K_M 15 s, each validation pass ~4-5 min. Validation loss 0.1024.
**Validation exact match: Q8_0 378/525 (72.0%), Q4_K_M 336/525 (64.0%)**; GGUFs 639 MB / 397 MB; median
0.48 s a turn. Per expected kind (Q8_0): which 70/75, call 106/165 (41 answered none), card 41/105 (78
gave a card, often another card or other args; 27 none), none 108/120, yours 53/60. The trial never saw
the held-out set (HELDOUT=no).

**The next session reads** `~/scratch/yames-c3d/runs/<candidate>/STATUS` (one line per stage, the log
of any failure) and `RESULT.md` (the candidate against stock-4b and stock-8b); then
`node evals/coach/train/env/tabulate.mjs --all ~/scratch/yames-c3d/runs evals/coach/results/<date>-c3d2.md`
for the combined table, and commits it.

**Re-submit** (continues where it stopped; training resumes from its last checkpoint): the same command
with a new name, e.g.
`job submit --name coach-c3d2-b1-06b-full-2 --ram 16G --gpu 20G --est 8h --lock coach-c3d-train --cwd ~/scratch/yames-c3d/code/b5170fca -- bash ~/yames-coach-build/plans/coach/tools/run.sh bash ~/scratch/yames-c3d/code/b5170fca/evals/coach/train/env/pipeline.sh b1-06b-full ~/scratch/yames-c3d/code/b5170fca/evals/coach/train/env/configs/b1-06b-full.sh`.
To redo one stage, move its output aside (e.g. `val/<label>/val.json`, `SELECTED`); never re-run the
held-out stage to choose anything (`heldout/COUNT` counts the runs).

## Proven / not proven

- Proven by the trial or the stock job: render, lengths, LoRA train, merge, both converts, validation,
  select, held-out alone + both chains, tabulate. Resume and epoch snapshots: `resume_check.sh` (926).
- Not proven before the candidates reach it: the full fine-tune's convert of `epoch-1` (written by the
  new `save_model`, a bf16 copy of the fp32 master; the final model takes the old, proven path), and
  the 1.7B / 4B merges at this size. A failure stops that job at that stage with its log in STATUS;
  fix, re-snapshot, re-submit.
