## Decisions and why

- **The snapshot is the last event of each kind**, plus a `seq` across kinds so a surface can tell
  which of two kinds came last. Built lazily on the first read after a publish, so a publish nobody
  reads allocates nothing beyond the event. `publish` stamps `seq` onto the event object in place:
  publish a freshly built object, never one you keep. A listener that throws is logged; the others
  still hear the event and the publisher never sees the failure.
- **The Session publishes through a wrapped dispatch, not a line beside each dispatch.** The leg file
  says one line beside each existing dispatch; there are about 25 dispatch sites in `useSessionRun.ts`,
  and `stepReady` alone comes from start, jump, next, again, back, the placement insert and more.
  `useCoachPublishingDispatch` wraps `dispatch` once and reduces each event a second time against a
  mirror of the state (`runReducer` is pure: every event carries its own `now`), so the coach hears
  exactly each transition, two dispatches in one commit as two events. The cost is one extra
  reduction per dispatch (the busiest is the one-second tick); nothing per beat. The only per-call
  change is `dispatch({ type: "takeResult", ... }, attempt.review)`. This also keeps the hunks in the
  shared file at three, which is what c1a's merge needs.
- **`takeResult.review` is null for an ungraded Take**, whatever review is lying about from an earlier
  pass. A graded Take carries `attempt.review` whole, `findings` included (the Session itself still
  reads only `review.segment`).
- **Token estimate**: ASCII at 3 characters a token (English runs about 4 in Qwen3 / Llama 3, so this
  over-counts), any other character 1 token, CJK and above U+2E80 1.5. Lines are added most important
  first; one that does not fit is skipped whole and a shorter later one tried; the first line (screen,
  language, grading, input) is clipped to fit rather than dropped. The test holds caps 450 to 25 in
  English and Chinese.
- **The source is the caller's to say**, never the model's: `ResolveOptions.source` goes onto every
  `text` block that resolves, and only text blocks (the line goes under the words it vouches for, not
  under a drawing or a button). The model's catalogue has no such field.

## Where the design differs from the code

- `brain.tier: BrainTier` is `brain.choice: string` (the selector's pick: "off", a local model's id,
  later "cloud"), per the leg file.
- `exercise` travels with `variantSeed` and `words` (`exerciseWords(exercise, withVariant(...))`), the
  design's comment made into fields.
- `song.range` is the real `BarRange` type (`startBar`, `endBar`).
- `takesHere` is filled by `buildCoachContext` itself (`takesOf(progress, path.id, exercise.id)`,
  newest five) when both a path and an exercise are given; it is not a getter.

## For the next legs

- **Publish**: `import { publish } from "src/coach/bus"`; `publish({ type: "jamStopped", at: Date.now(), heard })`.
  Every event needs `at`. The milestone events (`cleanTempoMoved`, `stepOpened`, `levelDone`,
  `pathDone`), `jamStopped`, `songPassReviewed`, `toolRunEnded` and `appOpened` are typed and
  published by nobody yet.
- **Subscribe**: in a component, `useCoachEvent("takeResult")` (re-renders only when that kind is
  published again). Outside React, or to see every event, `subscribe(listener)` (returns the
  unsubscribe). `getSnapshot().last` has the last of every kind.
- **Build the context**: keep a `CoachSources` object of getters (refs) in the host and call
  `buildCoachContext(latest)` from a handler or an event, never in a render. `contextForModel(ctx)`
  for a model prompt.
- **Set a block's source**: `resolveCoachAnswer(answer, ctx, { source: { kind: "measured", take: 2 } })`;
  kinds `measured { take? }`, `path { step? }`, `app`, `general`. Strings under `coachBlocks.source.*`.
- **Not done here (by the leg file or by design)**: no host builds a `CoachContext` yet; tapping the
  source line does not open what it cites (DESIGN 3.6 asks for it; no leg in M1 owns it yet).

## CoachContext fields with no source in the app yet

No host calls `buildCoachContext` yet, so in practice every field waits for a caller. Of the sources
themselves:

- `brain.choice`, `brain.resident`, `brain.fastEnough`: the model selector (ms1) does not exist yet.
  `brain.llmCompiled` exists (`coach::llm_compiled()` through `ipc.ts`).
- `screen`: the app has no single "where am I" value with the twelve names; the host maps its view
  (and the Paths screen's depth, for `path` / `step`) to them.
- Everything else has an existing source: `grading` (`session/grading.ts`), `input.listening` and
  `input.direct` (`directInput` in `MainWindow.tsx`), `input.failure` (`InputFailure`), `plan`, `run`,
  `path`, `step`, `exercise`, `lastTake` and `review` (`useSessionRun.ts`), `progress`, `due`
  (`session/rotation.ts`), `jam`, `song`, `tool` (`ToolsInfo`, `SessionReport`).
