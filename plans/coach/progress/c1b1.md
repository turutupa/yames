## Where things sit in the DOM (for c2a1's merge)

- Neck / tab view, ready and running: `.session-body[data-testid=session-take] > .session-mechlow > .session-col`,
  first child: the note (`section.coach-note[data-kind=ready]`) or the order (`.coach-order`). Then
  HandLine, the How fold, the band, ReadyInput. The action row is untouched:
  `.session-body > .session-actions > .session-go` (nudges and the big button).
- Runway: the note in `.session-compact > .session-brief`; the order in `.session-compact > .session-compact-coach`.
- Result: `.session-between > .session-col`: kick, DecidingNumber, CleanTempoLine, (EdgePanel), the note
  (`section.coach-note[data-kind=result]`, `aria-live=polite`), the big button, `.session-nudges`, FairTap.
- The session bar (`SessionBar`) is not touched.

## Decisions and why

- **The finding's headline** (`findingText`): a pass with a place says "Passed at 90." then where it
  caught you and last Take; a pass without one keeps the existing `takeLine` sentence. Below the pass
  mark on timing: where, then which way, and nothing else (the number above says what decided it).
  Below it on notes heard / extras / pitch: the existing lead sentence first, then the place. Every bar
  of the tune on the same rounds is said as "the whole tune" (`place.*.all`, new) rather than "bars 1 to 4".
- **One quiet line under a finding**: the repeat line (third time) if any, else the first history line
  that is not `newClean` (the clean-tempo line above the note already says it).
- **The ready note, first Take**: headline = the Exercise's `coachLine`, source "From the Path · Step N",
  then `reasonLine(step.why)` and the honest line (first Take of the Session only). Later Take: one line,
  "Last Take: 79% even." plus the place and direction from that Take's note. The pass mark moved out of
  the coach's line to the head, beside the tempo, as in mock 03.
- **Short and narrow windows** (height under 760, or 481 to 700 wide and under 900 tall): the ready note
  is its headline and chips, side by side when there is room; no source, no quiet lines. With the input
  failed it steps aside entirely, as the old coach line did.
- **"Hear it first"** is shown only when Watch would play sound (`watch.hasSound && soundOn`), so the chip
  never plays a silent preview; it calls the same `watch.toggle` the Watch button does.
- **"What should I try?"** opens the How fold on the ready screen (scrolls it into view) and opens the
  how-to lines inside the note on a result. No Ask chip anywhere (no `onAsk` yet).
- **Ungraded**: the question is the author's `selfCheck[0]` (the played variant's first); without one the
  headline is the `coachLine` and nothing is asked after the Take. "I'm not listening this time, so you're
  the judge." once per Session (not when the input is the reason). The answer is asked on the ungraded
  result; "Last one: {{question}}" on a later ready screen only when it was left unanswered.
  `session.note.ungraded.didThey` carries `{{question}}` (c1a proposed it without arguments).
- **Recap line**: when the last Exercise played comes back (`parkedUntil`, else the review date from
  `reviewStateOf`, which is what `dueReviews` reads, else "next Session"), after "Passed at N" / "Clean
  tempo still N" / "Last played at N"; a clean tempo that rose is the recap's own headline, so not repeated.
- **Plural keys** follow the repo's convention: bare key + `_other` (plus `_few` / `_many` where a locale
  needs them), never `_one` (the coverage test reads the bare key as the singular).

## What the design got wrong about the code

- **There is rarely a ready screen between two Takes.** "Go again" (`again`, and `go` when the big button
  is Go again) sets `autoStart` and goes straight into the count-in; only Slower / Faster from a result
  (or coming back to an Exercise) shows the ready screen of a later Take. So mock 03's note is seen after
  a tempo nudge, and mock 04's "Last one: did they?" on a ready screen almost never; the answer lives on
  the ungraded result instead. The buttons were left as `bigAction` decides (the leg's rule).
- `noteVerdicts` are not held by the Session, so `tuningSuspected` is always false here (it is never said
  anyway, owner decision 9).
- DESIGN's ready mock shows "Take 2 · 10 bars ·" before the pass mark; the head shows the pass mark alone.

## The Take's order: cues too long

825 of 1010 Exercises have an English `coachLine` over 48 characters, so their Takes show no order until
leg c4c writes short cues. The list, per Path: `plans/coach/progress/c1b1-long-cues.txt`. Many of the
185 that fit are not orders ("Band on. Right notes and time after the take."); c4c should replace those
too. The limit is applied at run time to the text in the player's language.
