## Decisions

- **Which table, and why.** `cleanTempoOf` reads `exercise_ceilings`, which keeps only the highest clean
  tempo and no history, so the history has to come from `path_takes`. The rows that raised the clean
  tempo are exactly those with `facts.newClean = true` (`useSessionRun` sets it in the same place it
  hands `save_path_take` a clean tempo). The query reads those, plus caught + passed.
  Rows from before `newClean` existed (2026-11-08 to 11-16): `measures.pass.countsForCleanTempo` when the
  scorer answered, else `bars >= 8`, which is `countsClean` in `ProgressView.tsx`. Facts that are not
  JSON read as "no flag" (guarded with `json_valid`, so one bad row cannot fail the query).
- **"Marked not fair" is NOT left out.** The brief asks to leave out a Take marked not fair "exactly as
  `cleanTempoOf` leaves it out", but `cleanTempoOf` does not leave it out: answering "no" re-saves the
  row with no clean tempo and the ceiling keeps what it had. Following judgement call 12 ("computed as
  `cleanTempoOf` does"), the span keeps it too, so `bestBpm` always equals the ceiling Progress shows.
  A test pins it. If the owner wants unfair Takes out of milestones, c4b2 can filter (or the ceiling
  itself should change: that is a product decision, not this leg's).
- **First and best**: first = the earliest counted Take; best = the highest tempo, earliest Take on a tie.
  Folded in Rust (a `BTreeMap` keyed by Path then Exercise), independent of row order. Same Exercise id
  on two Paths = two entries, as the ceiling's key `<path>/<exercise>` has it.
- **The plan.** Every Take is a candidate, so the query reads the whole table whatever index it uses
  (the clean flag lives inside `facts_json`; only an expression index or a new column could narrow it,
  which is a schema change and not warranted at the measured time). `ORDER BY exercise_id, started_at
  DESC` lets SQLite walk `path_takes_exercise` with no temp B-tree. Plan and time below.
- **Week start**: nothing in the app computed a week start before (grepped). `weekStartOf` reads
  `Intl.Locale` week data (`getWeekInfo()` / `weekInfo`), else the region (maximized when the tag names
  none) against CLDR's Sunday / Saturday lists, else Monday.
- `weekTotals` takes `paths` as well as the brief's `(takes, now, weekStart)`: minutes need each
  Exercise's meter, as `totalsFrom` does.
