# Pitch fixtures

What `pitch.rs` gets right, in numbers. The harness is
`src-tauri/tests/pitch_fixtures.rs`; this folder holds the generator it
builds its audio with.

**There are no golden files here, and there should not be.** A golden
records what the code did; these fixtures record what the note *was*. A
change that makes the tracker worse therefore fails instead of being
re-baked — which is the opposite of how `dsp_fixtures` and
`highbpm_fixtures` work, and deliberately so: those pin a scoring formula
that is a judgement call, and this pins a measurement that has a right
answer.

## Running them

```sh
npm run test:pitch
node scripts/rust-test.mjs --test pitch_fixtures -- --nocapture
node scripts/rust-test.mjs --release --test pitch_fixtures -- --nocapture
```

`--nocapture` is where the numbers are. Every gate prints its accuracy line
and names every note that missed.

The **run-time gate asserts in release only** — a debug build is fifteen
times slower and failing on it would say nothing about the shipped binary —
but the measurement prints either way.

## Looking at one

```sh
DUMP_FIXTURE_WAVS=1 node scripts/rust-test.mjs --test pitch_fixtures
cargo run --release --manifest-path src-tauri/Cargo.toml --bin pitch-inspect -- \
  src-tauri/target/pitch_fixtures/sixteenths_160bpm.wav --guitar --frames
```

The WAVs land in `src-tauri/target/` and are not committed: they are
regenerated byte for byte by the seeded generator, so committing them would
be committing a cache.

## The six

| Fixture | What it is | Range |
|---|---|---|
| `scale_two_octaves` | A natural minor, A2→A4 and back, 120 BPM eighths | guitar |
| `scale_one_wrong_one_omitted` | the same run, one note a tone sharp, one not played | guitar |
| `scale_detuned_30_cents` | the same run, every note 30 cents sharp | guitar |
| `sixteenths_160bpm` | E minor pentatonic, 93.75 ms a note | guitar |
| `scale_click_bleed_20db` | the scale with the metronome leaking in 20 dB under it | guitar |
| `bass_low_e_line` | every note the three shipped bass banks hold, from E1 up | bass |

## Where the ground truth comes from

**The guitar fixtures are synthesised** (`synth.rs`) — extended
Karplus–Strong, because what breaks a pitch tracker is a strong second
harmonic, inharmonic partials, a broadband attack and a decay that takes the
periodicity away while you are still measuring it, and a sine has none of
those. The generator is checked against an *independent* measurement of its
own output by `every_synthesised_note_is_the_pitch_it_claims` — long-window
autocorrelation sharing no code with `pitch.rs` — because a fixture whose
ground truth is a comment is not a fixture. It currently comes out within
0.13 cents.

**The bass fixture is real recorded bass**: the shipped sampled banks under
`sounds/voices`, whose file names carry the MIDI number of the note that was
recorded. It is the best ground truth in the tree and it is where the "zero
octave errors" gate lives, because the low notes of a real bass are where a
difference function is most tempted by the subharmonic.
`every_sampled_bass_note_is_the_pitch_its_name_claims` checks the *library*
the same way (worst: 8.9 cents, upright F#3) so that a mislabelled sample
could never make the octave gate meaningless.

If `sounds/voices` is not in the checkout — `build.rs` says it may not be —
the bass fixture is skipped with a printed sentence rather than failing.

## Adding one

Add a `f_<name>()` returning a `Fixture` and put it in the list the gate it
belongs to iterates. A fixture needs, per note actually played: an onset
time (with jitter on it — a real detector does not land on the sample the
note started at) and the true pitch as float MIDI. Nothing else.
